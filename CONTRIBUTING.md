# Contributing to OakNexis projects

## Branches

- `main` — production-ready code, protected
- Feature branches follow the pattern `OAKN-XX-short-description`

## Commits

Use the format: `OAKN-XX: short description in sentence case`

Keep commits focused — one logical change per commit.

## Pull requests

- Open a PR for every change, including small fixes
- Fill in the PR template — summary, related issue, and test plan
- PRs require at least one approval before merging
- Squash merge into `main`

## Code review

- Review within one business day
- Approve only when the code is ready to ship — use "Request changes" otherwise
- Comments should be specific and actionable

## Reporting issues

Use the issue templates in this repository. Include steps to reproduce for bugs, and clear problem statements for feature requests.
